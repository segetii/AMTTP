\textbf{1.\enspace AMTTP: Pre-Settlement Compliance Infrastructure}

My core project is the Anti-Money Laundering Transaction Trust Protocol (AMTTP).

Existing compliance systems---both in traditional finance and blockchain---operate after transactions are executed, limiting their ability to prevent risk. AMTTP introduces a pre-settlement model, where compliance decisions are enforced before transaction finality within the Ethereum block window ($\sim$12 seconds).

The system performs:
\begin{itemize}[nosep, leftmargin=2em]
  \item Machine learning risk scoring
  \item Graph-based relationship analysis
  \item Sanctions screening
  \item Policy enforcement
\end{itemize}
before allowing transactions to proceed.

\textit{Architecture Overview}

AMTTP is implemented as a four-layer system:
\begin{itemize}[nosep, leftmargin=2em]
  \item \textbf{Client Layer:} Open-source SDKs (TypeScript and Python) with 17--19 service modules (risk, KYC, transactions, disputes, sanctions, monitoring).
  \item \textbf{Compliance Layer:} 7 parallel microservices (ML engine, graph analysis, policy engine, sanctions, monitoring, geographic risk, explainability).
  \item \textbf{ML Pipeline:} Trained on 2.64 million Ethereum transactions, achieving ROC-AUC 0.9879.
  \item \textbf{Blockchain Layer:} 18 Solidity smart contracts enforcing decisions (Approve, Review, Escrow, Block).
\end{itemize}

The system runs across 17 containerised microservices, with API gateway security, cryptographic signing, rate limiting, and monitoring.

I also developed:
\begin{itemize}[nosep, leftmargin=2em]
  \item A cross-platform Flutter application (6 platforms)
  \item A Next.js compliance dashboard (``War Room'')
  \item Wallet integrations for real-time user interaction
\end{itemize}

\textbf{2.\enspace Privacy-Preserving Compliance (zkNAF)}

To address the conflict between regulatory transparency and user privacy, I developed zkNAF, a zero-knowledge compliance framework.

It enables:
\begin{itemize}[nosep, leftmargin=2em]
  \item Sanctions verification without revealing identities
  \item Risk validation without exposing scores
  \item KYC confirmation without disclosing personal data
\end{itemize}

This allows compliance enforcement while maintaining alignment with GDPR data minimisation principles.

\textbf{3.\enspace Research: Blind Spot Decomposition Theory (BSDT)}

Alongside the engineering work, I developed Blind Spot Decomposition Theory (BSDT).

BSDT addresses a key limitation in machine learning systems: the inability to detect risks arising from hidden or unobserved factors. It provides a structured framework for identifying these ``blind spots'' and improving detection performance without retraining models.

This work has been validated across multiple datasets and domains, forming the analytical foundation of the AMTTP risk engine.

\textbf{6.\enspace Commercial Strategy \& Market Potential}

The commercial gap AMTTP fills is significant. Current on-chain compliance providers (e.g., Chainalysis, Elliptic, TRM Labs) operate almost exclusively post-settlement, which exposes institutions to irreversible operational risk once funds have moved. AMTTP provides the missing infrastructure for pre-trade compliance---an absolute requirement for regulated financial institutions and Virtual Asset Service Providers (VASPs) entering decentralised finance (DeFi).

From a scalability and commercial readiness perspective:
\begin{itemize}[nosep, leftmargin=2em]
  \item The system architecture successfully supports batch-scoring up to 10,000 transactions simultaneously.
  \item The smart contract layer is actively deployed and validated on the Ethereum Sepolia testnet.
  \item The design explicitly caters to FCA and FATF Travel Rule obligations, enabling fluid compliance without compromising GDPR principles.
\end{itemize}

By providing a ``Compliance-as-a-Service'' (CaaS) API that computes verdicts within the $\sim$12-second block confirmation window, AMTTP holds clear commercialisation potential within the B2B enterprise fintech sector. My UK patent establishes the defensive moat necessary to commercialise this product.
